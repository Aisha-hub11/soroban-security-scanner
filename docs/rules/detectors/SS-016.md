# SS-016 — Unbounded data stored in instance storage

- **Severity:** medium
- **Confidence:** low
- **Category:** storage

## Problem

Instance storage is loaded for every invocation and has strict size limits.
Storing repeated distinct keys, or growing a collection, in instance storage
increases the cost of every call and can break the contract at scale.

## How it is detected

For every public `#[contractimpl]` entry point, the detector collects
instance-storage `set` calls. It reports when at least two `set` calls use
distinct key arguments. It also reports `push`/`push_back`/`push_front` when the
same function reads from instance storage.

## Limitations

- Key variability is inferred from the rendered first argument; two constants
  are distinct, but runtime-computed keys may be missed or over-reported.
- Does not measure entry size or count.
- Helpers are not traced.

## False positives

- Small, fixed configuration that happens to use several instance keys.
- Bounded collections whose size is checked in a helper.

## Remediation

Keep instance storage for small, fixed configuration. Store growing collections
in persistent storage, and bound their size explicitly.
