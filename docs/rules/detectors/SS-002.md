# SS-002 — Cross-contract call without caller authorization

- **Severity:** high
- **Confidence:** low
- **Category:** cross-contract

## Problem

A public contract function constructs and calls another contract's client but
does not call `require_auth`. If the contract acts with its own authority, an
attacker may trigger cross-contract effects without approval.

## How it is detected

Detects associated-function calls of the form `<Name>Client::new(...)` inside a
public `#[contractimpl]` function whose facts — merged with the same-file helper
functions it calls (bounded depth) — contain no `require_auth` call. Each
constructor is reported unless its address argument is trusted configuration:
a string literal, a storage read, or `current_contract_address()`. Untrusted
parameters and arbitrary expressions are still reported.

## Limitations

- Only recognizes the generated-client constructor pattern
  (`*Client::new`).
- Provenance is syntactic. A storage read is assumed to be admin-configured and
  trustworthy; the detector does not follow how that value was validated.
- Authorization is followed through helper functions defined in the **same file**
  (bounded depth), but not across files or into the called contract.

## False positives

- Permissionless invocations, or where the called contract enforces
  authorization itself.
- Calls made through manually written interfaces rather than a generated client.
- Hardcoded or storage-configured client addresses are treated as trusted and
  are not reported.

## Remediation

Authorize the caller with `require_auth` before invoking another contract on the
contract's behalf, and bind approval to the operation's arguments. Verify that
any address used to construct a client is the expected contract.
