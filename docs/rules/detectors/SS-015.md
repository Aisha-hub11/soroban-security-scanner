# SS-015 — Deprecated Soroban SDK version

- **Severity:** low
- **Confidence:** medium
- **Category:** dependencies

## Problem

A project declares a `soroban-sdk` version older than the supported minimum.
Older major versions can miss API fixes, security patches, and current runtime
behavior. This is a policy signal rather than proof of a vulnerability.

## How it is detected

The rule reads `Cargo.toml` manifests, finds the `soroban-sdk` dependency, and
compares the first numeric version in its requirement against
`minimum_soroban_sdk` (default `21.0.0`). The finding is reported at the manifest
path, line 1, with the declared requirement as evidence.

## Configuration

Set the policy in `soroban-scan.toml`:

```toml
minimum_soroban_sdk = "21.0.0"
```

The value is documented in [Configuration](../../configuration.md).

## Limitations

- Compares only the first numeric component group; pre-release and patch-level
  policy are not modeled.
- Workspace inheritance (`workspace = true`) without a version is not reported.
- A project may intentionally pin an older SDK while migrating.

## False positives

- Vendored or forked SDKs whose version string does not reflect the patched
  code.
- Projects that must target an older SDK for network compatibility.

## Remediation

Upgrade `soroban-sdk` to at least the configured minimum, rebuild, and rerun the
contract tests.
