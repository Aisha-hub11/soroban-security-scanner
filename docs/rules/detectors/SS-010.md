# SS-010 — Privileged state change without an event

- **Severity:** low
- **Confidence:** low
- **Category:** events

## Problem

Privileged state changes such as updating an admin, pausing a contract, or
changing fees and oracle parameters are often invisible off-chain when no event
is emitted. Indexers, dashboards, and incident responders cannot observe the
change, which weakens the audit trail around sensitive operations.

## How it is detected

For every public `#[contractimpl]` entry point, the detector inspects storage
mutations (`set`, `remove`, `update`, `extend_ttl`, `set_ttl`, `bump`). A finding
is reported when the mutation text mentions one of the privileged key hints and
the function does not call `env.events().publish(...)`.

The built-in key hints are:

`admin`, `owner`, `pause`, `param`, `config`, `fee`, `oracle`, `governor`,
`role`, `authority`, `operator`, `treasury`.

The list is exposed as `rules::missing_events::PRIVILEGED_KEY_HINTS` so it stays
explicit and can be extended in one place.

## Limitations

- Purely syntactic and name-based; a key can be privileged without matching a
  hint, and a matching name can be non-privileged.
- Only events published in the same entry point are considered. Helpers are not
  traced.
- Emitting an event with empty or misleading data still satisfies the check.

## False positives

- Privileged writes whose event is published in a called helper.
- Keys that contain a hint substring but are not privileged configuration.
- Contracts that intentionally rely on transaction results rather than events
  for auditability.

## Remediation

Publish an event for every privileged state change with
`env.events().publish(...)`, including the previous and new values where
practical. Keep the event schema stable so indexers can rely on it.
