# SS-009 — Insecure randomness derived from ledger state

- **Severity:** medium
- **Confidence:** low
- **Category:** arithmetic

## Problem

Contracts may derive randomness from `env.ledger().timestamp()` or
`ledger().sequence()`. Both values are publicly observable and can be influenced
by transaction submission timing, so an attacker may be able to predict or steer
the result. This is especially dangerous for lotteries, winner selection,
shuffling, and any other value-dependent decision.

## How it is detected

For every public function inside a `#[contractimpl]` block, the detector looks
for method calls on a `ledger` chain named `timestamp` or `sequence`. It then
checks whether the same function contains a binary comparison, remainder (`%`),
or arithmetic expression (`+`, `-`, `*`) whose rendered text includes the ledger
accessor. A finding is reported at the ledger accessor with the enclosing
expression as evidence.

## Limitations

- Purely syntactic; no data-flow, type, or range analysis. It cannot prove that
  the ledger value is used as randomness or that an attacker can control the
  outcome.
- Reports **low confidence** for exactly this reason; treat findings as review
  prompts, not confirmed vulnerabilities.
- Only `timestamp` and `sequence` accessors are recognized. Other predictable
  inputs (for example, the current ledger number) are not covered.
- Arithmetic or comparisons performed in a called helper are not traced across
  call boundaries.

## False positives

- Expiry checks that compare the timestamp against a stored deadline (for
  example a value read from storage or a variable named `deadline`, `expiry`, or
  `ttl`) are excluded.
- Reading a timestamp without using it in a comparison, remainder, or arithmetic
  expression does not trigger the rule.
- Logging or returning the current time for display purposes is not flagged.

## Remediation

Do not derive randomness from `ledger().timestamp()` or `ledger().sequence()`.
Use a commitment/reveal scheme, a verifiable randomness source, or another design
that does not depend on values the submitter can observe or influence. If the
value is only used for an expiry check, document that use and suppress this rule
for the function.
